# Доставка обновлений Socket

Релизы `IIchikadev/Socket` содержат `Socket.loader.exe` для первой установки и `socket-update.zip` для автоматической доставки ядра. Публичного отдельного JAR и файла SHA256 не требуется.

После сборки клиента с той же версией, что в `loader-source/package.json`, выполните `npm run dist`. Скрипт создаёт оба артефакта. ZIP содержит `update.json` (протокол 1, версия, Minecraft, имя ядра, SHA256) и одно производственное ядро. QA entrypoint не допускается. При публикации тэг должен точно совпадать с версией, например `1.2.1`.

Проверка релизов выполняется при открытии лоадера и перед запуском. Новые установки включают автообновление по умолчанию; ранее сохранённый выбор сохраняется. Пререлизы устанавливаются только при явном включении соответствующей опции. При недоступной сети или ошибке обновления игра использует имеющееся ядро.

Загрузка разрешена только из релизов этого репозитория по HTTPS. Проверяются SHA256 архива, если GitHub вернул digest, SHA256 вложенного JAR, Fabric ID, версия ядра, версия Minecraft и протокол. Из ZIP извлекается только файл с проверенным именем, произвольное извлечение архива не используется.

Ядро кешируется в `%APPDATA%\.socketclient\cores\<версия>`. Перед заменой старое ядро перемещается в `backups/core-<время>`, при ошибке возвращается назад. Настройки выбранной версии записываются после успешной установки. Запуск игры и замена ядра исключают друг друга внутри одного лоадера. Новая кешированная версия имеет приоритет над старым ядром внутри EXE. Личные конфиги и другие моды сохраняются.

Протокол 1 обновляет ядро для Minecraft 1.21.4. Новые зависимости, другая версия Minecraft или изменения самого EXE требуют расширения протокола либо новой версии лоадера. Лоадер 1.2.0 не поддерживал служебный ZIP, поэтому переход на 1.2.1 выполняется один раз скачиванием EXE.

Проверка: `node --test tests/updates.test.cjs` в `loader-source` проверяет успешное обновление, сохранность чужого мода, повреждение архива, несовместимость Minecraft, восстановление при ошибке файловой системы и работу при недоступной сети.
